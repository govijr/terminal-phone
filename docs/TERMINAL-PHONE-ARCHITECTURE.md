# Phone agent architecture

The product has three boundaries:

1. **TerminalPhoneCore** defines versioned Codable request/reply types, the `PhoneBackend` protocol, accessibility normalization, session semantics and private Unix-socket framing. It knows nothing about idb, WDA, terminal rendering or MCP.
2. **Platform adapters** in TerminalPhone implement `SimulatorPhoneBackend` and `DevicePhoneBackend`. The simulator uses persistent idb clients for inspection and serialized input; WDA uses a persistent Swift HTTP client and native XCTest element actions. Device management continues through the existing explicitly targeted `simctl` and `devicectl` paths.
3. **Front ends** translate CLI arguments and MCP tools into the same requests. The terminal viewer remains a separate video consumer and sends input through that shared session. It never takes an independent lease that would disable the agent or itself.

`PhoneAgentSession` owns current observations, reference validation, semantic selection, postcondition polling, request deduplication and action receipts. A scene is compared structurally before reference input: normalized elements, app identity, dimensions, scale and orientation must still match. This is conservative and deliberately rejects changes in unrelated visible content. Capture is sequential and timestamped, not atomic. A target can still change between inspection and native input; WDA additionally resolves its native locator and checks bounds, while idb uses freshly validated accessibility bounds. Neither is claimed to eliminate all UI races.

The host accepts bounded concurrent connections. Agent operations use one FIFO queue, while viewer input and status requests remain responsive during an agent read or wait. A separate priority queue serializes native input only. Human input increments a generation counter that cancels outstanding agent inspection/verification and invalidates references before further native input can be sent. Simulator inspection and input use independent persistent connections, so a slow accessibility read cannot hold the touch connection. The core rejects concurrent direct agent operations while allowing the viewer input path. A host lazily acquires an input lease and releases it only on explicit release/stop or idle exit. Other phones have independent hosts. Registration grants are reloaded before every request; a session's UDID cannot silently change.

Local sockets live in a verified user-owned 0700 directory under `/tmp`, use 0600 permissions, validate peer ownership and bound frame sizes. Endpoint identity includes the canonical registry root and UDID; the controller lock includes only the UDID so separate registries cannot control the same phone concurrently. Filesystem locks prevent duplicate startup. Stop obtains the peer PID from the connected Unix socket, verifies its executable path, and signals that process; it does not trust persisted PIDs.

Client cancellation closes its IPC connection. The host skips disconnected queued requests, checks for cancellation immediately before input and checks again between verification captures. The normal request queue is independent from the signal-driven Stop path. Stop closes the adapter, terminates the simulator helper, removes the endpoint and releases ownership even during a request. Physical input already sent is irreversible. Transport failures after submitting an action are reported as unknown outcomes and never retried automatically.

Deduplication is bounded to 128 results in a live session. Optional expected session IDs prevent replay into a replacement host. Durable exactly-once semantics are not promised. Screenshots are private local artifacts, retained at most 16 per phone across host sessions. Accessibility secure values are omitted, but images are not pixel-redacted.

To add a backend, implement `PhoneBackend`: expose truthful capabilities, collect normalized scenes with display-point geometry and PNGs, perform one validated action, and close its resources. Keep backend-specific native targeting inside the adapter. The CLI, MCP schema and core reference/recovery rules should not need backend branches.

Tests use a fake backend to exercise wrong-screen rejection, grants, controller conflicts, result verification, duplicate requests and uncertain outcomes without touching a user's phone. Separate live acceptance checks use a dedicated simulator and the included demo app. Real-device acceptance remains a distinct hardware check.

MCP protocol references: [stdio transport](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports), [tools and image results](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).

Setup and installation live outside the adapters. PhoneSetup discovers a full Xcode without changing system xcode-select, installs a missing iOS runtime, and downloads checksum-pinned native control and standalone Python archives into a shared per-user cache. It never changes system Python or requires Homebrew. PhoneInstaller stages and verifies a versioned CLI bundle, atomically replaces only its own launcher, and backs up shell configuration before adding a command path. Public packages whitelist executable/resources/guide files and exclude personal device signing artifacts.
